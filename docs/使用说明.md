# rsagent 使用说明

## 1. 准备 auth key

1. 打开 Tailscale 管理后台，Settings → Keys → Generate auth key。
2. 勾选 **Reusable**、**Pre-approved**，并在 **Tags** 里选择一个 tag，例如 `tag:serial-agent`。
3. 复制生成的 `tskey-auth-...`。它最长 90 天有效，只影响新设备入网，已入网的设备不受影响。

为什么必须带 tag：不带 tag 的节点默认 180 天密钥过期，到期会掉线，需要有人到现场重新认证。带 tag 的节点默认不过期。

tag 需要在 ACL 的 `tagOwners` 里先声明，见第 4 节。

## 2. 远端安装

两种方式任选：

- **安装包** `rsagent-setup-<版本>.exe`：装到 `Program Files\RemoteSerial`，安装时可勾选开机自启（计划任务）、系统服务、防火墙规则，卸载时一并清理。升级直接运行新版安装包，它会先结束运行中的实例，服务已安装时自动换成新程序并重启。支持静默批量部署，见第 9 节。
- **绿色版** `rsagent-windows-amd64.exe`：复制到任意目录（建议 `C:\RemoteSerial\`），不要放在网络盘或 U 盘上。

然后：

1. 双击运行。托盘出现图标，窗口打开管理界面。若提示缺少 WebView2，程序会改用浏览器打开界面；可在"部署"页安装 WebView2。
2. 在 **Tailscale** 页粘贴 auth key，节点名默认 `rs-<机器名>`，点"登录"。几秒后状态变为"在线"，显示节点 IP 和 MagicDNS 名。填 OAuth client secret 时还要填 tag，见第 9 节。
3. 在 **串口桥接** 页"新增桥接"：选串口、波特率，TCP 端口默认从 2217 开始。勾选"USB 匹配"后即使 COM 号变化也能找到同一个设备。
4. 在 **部署** 页按站点情况选一条无人值守路线，见第 3 节。

登录状态保存在数据目录 `%ProgramData%\RemoteSerial\tsstate\`，重启后自动上线。auth key 本身不会保存。

## 3. 无人值守

### 路线 A：自动登录 + 计划任务（推荐给工控机）

1. 用微软 Sysinternals 的 [Autologon](https://learn.microsoft.com/sysinternals/downloads/autologon) 配置自动登录。它把密码存为 LSA secret，不是注册表明文。
2. 以管理员身份运行 rsagent 一次（右键"以管理员身份运行"），在"部署"页点"安装"计划任务。提权状态下安装的任务带最高权限，之后程序每次启动都是提权状态，远程操作部署页不再弹 UAC。
3. 现场有人经过时，再建一个"登录时触发"的计划任务执行 `rundll32 user32.dll,LockWorkStation`，登录后自动锁屏。锁屏不影响托盘程序。

计划任务的行为：用户登录 10 秒后启动，每 5 分钟检查一次，已在运行则不重复启动。结束进程后 5 分钟内会自动拉起。

### 路线 B：Windows 服务（不允许自动登录的站点）

在"部署"页点"安装并启动"服务。程序会被复制到数据目录的 `bin\` 下并用副本注册，core 以 LocalSystem 服务运行，开机即上线，不依赖登录。安装后当前进程的 core 停止，托盘与窗口自动连接到服务。以后双击程序只打开界面，托盘"退出"不影响服务。

在服务模式下点"停止"或"卸载"不需要 UAC，服务会由独立子进程停掉；托盘程序发现没有 core 响应且服务已不在运行，几秒后自动在本进程重新启动 core，界面随之恢复。更新程序后重新点一次"安装"即可替换副本。

服务失败后 5 秒自动重启。命令行等价操作：

```
rsagent service install | uninstall | start | stop | status
```

### 防火墙

"部署"页"添加"防火墙规则会放行 UDP 41641 入站，提高与本地设备直连的成功率。不加也能通过中转工作。

### Linux 站点

一键安装（下载对应架构的程序、注册 systemd 服务、可选自动入网）：

```sh
curl -fsSL https://raw.githubusercontent.com/mqvista/RemoteSerial/main/deploy/install.sh | sudo sh
# 带入网：
curl -fsSL .../install.sh | sudo RSAGENT_AUTH_KEY=tskey-client-xxx RSAGENT_TAGS=tag:serial-agent RSAGENT_HOSTNAME=rs-site1 sh
```

也可以用发布页的 `.deb`（`sudo dpkg -i rsagent_<版本>_arm64.deb`），或手工：

```
sudo ./rsagent-linux-arm64 service install     # 注册 systemd 服务并启动
./rsagent-linux-arm64 run --console            # 或前台运行调试
sudo rsagent provision --auth-key ... --tags tag:serial-agent   # 无人值守入网
```

Linux 没有桌面壳，登录 auth key 通过本机浏览器打开 `http://127.0.0.1:7890/` 操作，或用 SSH 端口转发，或用 `provision` 子命令。`/etc/default/rsagent` 里设 `RSAGENT_AUTH_KEY` 也能在首次启动时自动入网，入网后记得删掉。

## 4. ACL

最小规则：你的账号能访问 tag 节点的管理端口和桥接端口；子网路由自动批准。

```json
{
  "tagOwners": { "tag:serial-agent": ["autogroup:admin"] },
  "autoApprovers": {
    "routes": { "192.168.10.0/24": ["tag:serial-agent"] }
  },
  "acls": [
    {
      "action": "accept",
      "src": ["autogroup:member"],
      "dst": ["tag:serial-agent:80,443,2217-2299", "192.168.10.0/24:*"]
    }
  ]
}
```

说明：

- `80` 是管理界面，`2217-2299` 是桥接端口范围，按需调整。
- 要让两个 tag 节点互通（例如用 tsprobe 联调），再加一条 `src: ["tag:serial-agent"]`、`dst: ["tag:serial-agent:*"]`。
- 系统 `ping` 只有在目标端口写 `*` 时才通；`tailscale ping` 不受 ACL 限制。
- 管理界面还有一层白名单，在"设置"页填写允许的登录名。白名单为空时 tailnet 内所有人可访问，概览页会告警。

## 5. 本地连接

桥接有两种模式。**裸 TCP** 只传数据，参数在远端界面固定，任何 TCP 客户端都能连。**RFC2217** 让本地工具远程设置波特率、数据位、校验、停止位，拉 DTR/RTS，发 break，烧录 ESP32、STM32 这类靠控制线复位的设备必须用它。客户端断开后远端自动恢复界面上配置的参数，DTR/RTS 拉回高电平。

| 本地工具 | 裸 TCP | RFC2217 |
|---|---|---|
| 浏览器 | 管理页"终端"，不需要任何本地工具 | 同左 |
| nc / PuTTY raw / XCOM 网络模式 | `100.x.y.z:2217` | 不适用 |
| pyserial、miniterm | `socket://100.x.y.z:2217` | `rfc2217://100.x.y.z:2217` |
| esptool | 不适用 | `--port rfc2217://100.x.y.z:2217?ign_set_control`（去掉参数则由 esptool 控制 DTR/RTS 复位） |
| PlatformIO、idf.py | `socket://...` | `rfc2217://...` |
| 需要 COMx 的工具 | hub4com `com2tcp` | com0com 虚拟串口对 + hub4com `com2tcp-rfc2217` |

桥接还可以勾选"本机端口"，在远端的 127.0.0.1 上再开一个监听，供远端本机的串口工具使用。

一个桥接同一时刻只接受一个 TCP 客户端。"客户端策略"决定新连接是替换旧连接还是被拒绝。网页终端不占用这个名额，可以多人同时旁观。本地断网后远端靠 keepalive 在约 30 秒内释放串口，也可以在界面上"踢掉"。

## 6. 子网路由

在"子网路由"页加入远端局域网网段并保存。页面列出本机所在网段可一键加入。宣告后需要后台批准或 ACL `autoApprovers`。

限制：用户态转发只支持 TCP 和 UDP，`ping` 远端设备不通属正常；源地址做 SNAT，远端设备看到的是远端 PC 的 IP；不要宣告与本地重叠的网段。本地 Linux 客户端需要 `--accept-routes`。

## 7. 排错

- **节点一直"连接中"或"需要登录"**：auth key 无效、过期或已用完；重新生成一个。
- **节点"等待批准"**：auth key 没勾 Pre-approved，到后台 Machines 里批准。
- **节点在线几秒后变成"需要登录"，提示要求重新认证并给出链接**：控制服务器判定密钥过期、被撤销，或节点申请的 tag 和已有的不一致。在 Tailscale 页用 auth key 重新登录（会保留节点身份，不生成新节点），或用 tag owner 的账号在浏览器打开那个链接。登录时填过的 tag 会存进配置，之后每次启动自动带上。
- **本地打不开管理页但 ping 通**：检查 ACL 是否放行 80 端口；地址栏要带 `http://`；MagicDNS 未启用时用 IP。
- **桥接"等待设备"**：串口不存在或被其他程序占用，拔插设备或关闭占用程序，程序每 3 秒重试。
- **直连还是中转**：Tailscale 页"对端"表的"链路"列。全是中转时可在自有服务器上部署 peer relay 或 DERP。
- **日志**：日志页看最近 1000 行；文件在数据目录 `logs\rsagent.log`。

## 8. 数据目录

| 平台 | 默认位置 |
|---|---|
| Windows | `%ProgramData%\RemoteSerial\` |
| Linux（root） | `/var/lib/rsagent/` |
| Linux（普通用户） | `~/.local/share/rsagent/` |

内含 `config.json`（配置）、`tsstate\`（节点私钥，勿外泄）、`logs\`、`update\`（已下载的新版本）。可用 `--data-dir` 或环境变量 `RSAGENT_DATA_DIR` 覆盖。单进程模式和服务模式共用同一目录。

## 9. 批量部署（OAuth client）

auth key 最长 90 天有效，批量部署多个站点时用 **OAuth client secret** 更省事：它不过期，每次入网由程序自己向 Tailscale API 换取一次性 auth key。

1. 后台 Settings → OAuth clients → Generate OAuth client，勾选 **Auth Keys** 的 Write 权限，Tags 选 `tag:serial-agent`。得到 `tskey-client-...`。
2. 用它登录时必须指定 tag（界面上的"Tag"栏，或命令行 `--tags`），tag 必须在 OAuth client 允许的范围内。程序会自动加上 `ephemeral=false&preauthorized=true`，节点是永久的、不需要批准。

Windows 静默安装并入网：

```
rsagent-setup-0.4.0.exe /VERYSILENT /SUPPRESSMSGBOXES /NORESTART ^
  /AUTHKEY=tskey-client-xxxx /TAGS=tag:serial-agent /HOSTNAME=rs-site1 /TASKS="autostart,firewall"
```

`/TASKS` 可选 `autostart`（计划任务）、`service`（系统服务）、`firewall`、`desktopicon`；装为服务用 `/TASKS="service,firewall"`。Headscale 加 `/CONTROLURL=https://...`。安装完成后程序自动启动（服务模式下服务已在运行）。

已安装的机器也可以在命令行入网：

```
rsagent provision --auth-key tskey-client-xxxx --tags tag:serial-agent --hostname rs-site1
```

本机有 core 在运行时交给它执行，否则临时起节点完成登录后落盘。key 也可用环境变量 `RSAGENT_AUTH_KEY` 传入，避免出现在命令行历史里。

## 10. 更新

"部署"页的"更新"卡片：检查 → 下载（SHA-256 校验）→ 应用并重启。程序启动 2 分钟后和每天各自动检查一次，有新版本时概览页提示，不会自动安装。

- 单进程模式：替换程序文件后本进程自动重启，几秒后界面恢复。程序目录当前用户不可写（如 Program Files）时弹 UAC。
- 服务模式：服务进程自己替换程序并重启；远端托盘程序发现 core 版本变了，会用同一份下载替换自己并重启。
- Linux：`sudo rsagent update`（`--check` 只检查）。systemd 下程序原地重启，PID 不变。

清单地址在"设置"页，默认指向 GitHub Releases 的 `manifest.json`。仓库私有或站点不能访问 GitHub时，把发布文件和 `manifest.json` 放到自己的 HTTP 服务器上，改清单地址即可；`build.ps1 -Manifest -BaseURL <地址>` 或 `make manifest` 生成清单。

命令行 `rsagent quit` 可让本机运行中的托盘实例退出（安装包升级时用它结束旧进程）。

## 11. OpenWrt

支持 x86_64 软路由与 aarch64 设备（如 RK3568），OpenWrt 24.10 与 25.x。程序与 Linux 版相同，启动时识别 OpenWrt 并改用下面的默认值。需要约 25MB 闪存空间（不含 tailscale 套件）。

### 安装

以 root 登录路由器后：

```sh
# 在线安装（路由器没有 curl 时用 wget）
wget -qO- https://raw.githubusercontent.com/mqvista/RemoteSerial/main/deploy/install.sh | sh
# 带入网
wget -qO- .../install.sh | RSAGENT_AUTH_KEY=tskey-client-xxx RSAGENT_TAGS=tag:serial-agent sh
```

在线安装使用套件：OpenWrt 24.10 为 `.ipk`（opkg），25.x 为 `.apk`（apk）。tailscale 与常见 USB 串口驱动（`kmod-usb-serial-ch341`、`-cp210x`、`-ftdi`、`-pl2303`、`kmod-usb-acm`）作为依赖自动安装；装好后服务已启动并设为开机启动，`tailscale0` 已加入防火墙区域，装有 LuCI 时一并安装 LuCI 页面（“服务 → RemoteSerial”，不需要时加 `--no-luci`）。

也可以从发布页下载套件手动安装（`aarch64_generic` 适用于 RK3568 等 armv8 设备，`x86_64` 适用于软路由）：

```sh
# 24.10
opkg update && opkg install ./rsagent_0.6.0-r1_aarch64_generic.ipk ./luci-app-rsagent_0.6.0-r1_all.ipk
# 25.x（套件未用 OpenWrt 的密钥签名）
apk update && apk add --allow-untrusted tailscale ./rsagent-0.6.0-r1_aarch64_generic.apk ./luci-app-rsagent-0.6.0-r1_all.apk
```

离线安装（或路由器架构没有对应套件时，脚本会自动改用这种方式）：从发布页下载 `rsagent-openwrt-<amd64|arm64>.tar.gz`，复制到路由器后：

```sh
tar -xzf rsagent-openwrt-arm64.tar.gz && sh rsagent-openwrt/install.sh
```

离线包直接安装文件：把程序装到 `/usr/bin/rsagent`；没有 tailscale 时询问是否安装（`--with-tailscale` 不询问直接安装，`--no-tailscale` 改用内建 Tailscale）；配置防火墙区域、注册 procd 服务并开机启动；装有 LuCI 时一并安装 LuCI 页面。USB 串口驱动需自行安装（套件名见上）。

### Tailscale

OpenWrt 上默认使用**系统自带的 tailscale**（tailscale 套件），rsagent 不再内嵌第二个节点：子网路由走内核，比内嵌节点快，路由器上也只有一个 Tailscale 身份。

管理界面的 Tailscale 页会依次检查并引导：未安装 → 一键安装；未运行 → 启动并设为开机启动；防火墙缺少 `tailscale0` 区域 → 一键加入；未登录 → 用 auth key 登录，或“在浏览器中登录”（显示链接与 QR 码，手机扫码即可）。

命令行同样可以完成：

```sh
rsagent tailscale status      # 检测结果
rsagent tailscale install     # 安装、启动、配置防火墙
rsagent tailscale start       # 已安装时启动并设为开机启动
rsagent tailscale firewall    # 只配置防火墙
tailscale up --auth-key ...   # 或直接用 tailscale 自己的命令登录
```

注意：

- 系统 tailscale 由路由器管理，rsagent 不会替你登出或停止它；节点名用路由器的主机名。
- 子网路由页只增删 rsagent 自己加的路由，你用 `tailscale set --advertise-routes` 或其他工具加的会保留。
- 系统模式下不提供 netcheck，请在路由器上执行 `tailscale netcheck`。
- 路由器无法连网时，在其他电脑下载 tailscale 套件复制过去，用 `opkg install ./tailscale_*.ipk`（25.x：`apk add --allow-untrusted ./tailscale-*.apk`）安装。
- 实在装不了系统 tailscale，可在 Tailscale 页点“改用内建”，或 `rsagent tailscale backend embedded` 后重启服务，改回内嵌节点（占用更多内存，子网路由较慢）。

### LuCI 页面

“服务 → RemoteSerial”提供常用操作，进阶功能（修改桥接参数、终端、录制、日志）仍在 rsagent 自己的管理界面：

- 服务状态、启动 / 停止 / 重新启动、开机启动开关；版本与一键更新（套件安装时）；
- Tailscale 详情：状态与 tailscaled 版本、节点 IP（IPv4 / IPv6）、MagicDNS 名称、Tailscale 网络、账号或标签、密钥到期时间；`tailscale0` 未加入防火墙区域时一键加入；

- Tailscale 引导：未安装、未运行时显示对应的一键按钮；未登录时可“在浏览器中登录”，或填 auth key / OAuth client secret（加 tag）登录，key 只用于这次登录，不会保存；
- 桥接列表与流量，单个桥接启用 / 停用 / 删除；
- 串口设备列表（设备名、芯片、USB ID、序列号、被哪个桥接使用），一键“新增桥接”：名称、波特率、模式（RFC2217 / Raw TCP）、TCP 端口，可选按 USB ID 匹配；
- 管理界面端口与“允许局域网访问”；
- **开启管理界面**：用一次性令牌跳转到管理界面并自动登录，不用另记密码。

页面跟随 LuCI 的语言（English / 正體中文）。rsagent 的提示与错误信息默认也跟随 LuCI：启动时读取 LuCI 的语言设置，LuCI 设为“自动”时以打开 RemoteSerial 页面时的实际语言为准（任何中文都使用正體中文）；在管理界面右上角手动选过语言后，则以手动选择为准。它通过 rpcd 插件 `luci.rsagent` 调用 `rsagent ctl`，受 LuCI 登录与权限控制；设置仍只存在 rsagent 自己的 `config.json` 里。

### Photonicat 2 小屏幕

在 Photonicat 2 上，可以在机身小屏幕上加一页「RemoteSerial」，显示 Tailscale 状态与 IP、节点名、桥接（已连接 / 启用）、当前客户端、收发速率和管理界面端口。按屏幕旁的按键翻页即可看到；这一页排在 GPS 页之前，原厂的其他页面不变。

- 用在线安装命令安装时，检测到 Photonicat 屏幕会一并安装套件 `rsagent-photonicat`；也可以手动安装该套件，或在 LuCI 的 RemoteSerial 页点“在小屏幕显示”。
- 移除套件（或点“移除”）后屏幕恢复原样；首次修改前的屏幕配置备份在 `/etc/rsagent/pcat2_mini_display-user_config.backup.json`。
- 命令行：`rsagent screen photonicat install | remove | status`。
- 数据来自 rsagent 每 2 秒写入的 `/tmp/rsagent/screen.json`（设置项 `statusFile`，其他显示设备或脚本也可以读取）。

### 访问管理界面

| 来源 | 地址 | 认证 |
|---|---|---|
| tailnet | `http://<路由器的 tailscale IP>:7890/`（80 端口留给 LuCI） | 与其他平台相同，见第 4 节 |
| 局域网 | `http://<路由器 LAN IP>:7890/`，需先打开“允许局域网访问” | 从 LuCI 的“开启管理界面”进入（一次性令牌），或局域网密码 |
| 路由器本机 | `http://127.0.0.1:7890/`（如 `ssh -L 7890:127.0.0.1:7890 root@<路由器>`） | 不需要 |

- **端口与局域网访问**在 LuCI 页或管理界面“设置 → 管理界面存取”修改，立即生效：先在新端口监听成功才关闭旧的，失败时保持原样；OpenWrt 上 tailnet 侧使用同一个端口。不能使用 22、53、80、443 和桥接端口。打开局域网访问时会在防火墙加一条 `rsagent_console` 规则（lan 区域放行该端口），关闭时删除。
- **局域网密码**（可选）让局域网设备不经 LuCI 也能登录：在“设置 → 管理界面存取”设置，或在路由器上执行 `echo '新密码' | rsagent ctl password`（`--clear` 清除）。修改或清除后所有局域网登录失效。登录状态只保存在内存里，rsagent 重启后需要重新登录。
- 这套规则在其他平台同样适用：本机监听收到的非回环请求一律视为局域网来源，必须登录。

### 命令行（rsagent ctl）

给 LuCI 与脚本使用，输出 JSON：

```sh
rsagent ctl status                        # 服务、管理界面、Tailscale、桥接
rsagent ctl service start|stop|restart|enable|disable
rsagent ctl bridge <id> start|stop
rsagent ctl ports                         # 串口设备
rsagent ctl bridge-add --device /dev/ttyUSB0 [--name n] [--baud 115200] [--mode rfc2217|raw] [--tcp-port N] [--match-usb]
rsagent ctl bridge-remove <id>
echo 'tskey-auth-…' | rsagent ctl tailscale-authkey [--tags tag:a]   # key 从标准输入读
rsagent ctl console --port 7890 --lan=true   # rsagent 未运行时直接改配置，下次启动生效
rsagent ctl token                         # 60 秒内有效的一次性登录令牌
rsagent ctl tailscale install|start|firewall ; rsagent ctl tailscale-job ; rsagent ctl tailscale-login
rsagent ctl update-check                  # 检查新版本
rsagent ctl update                        # 套件安装时一键更新（后台检查、下载、安装）
```

### 目录与服务

| 项目 | 位置 |
|---|---|
| 程序 | `/usr/bin/rsagent` |
| 配置与节点状态 | `/etc/rsagent`（写入 `/lib/upgrade/keep.d/rsagent`，升级固件后保留） |
| 日志与录制 | `/tmp/rsagent`（内存，重启后清空，避免磨损闪存） |
| 服务 | `/etc/init.d/rsagent start｜stop｜restart｜enable｜disable` |

### 更新与移除

- **用套件安装的**：一键更新。LuCI 页面的“版本”一栏显示新版本时点“更新”，或在管理界面“部署”页下载后点“应用”。rsagent 从发布页下载新的 `.ipk` / `.apk`（按清单校验 SHA-256），交给 opkg / apk 安装；安装时 rsagent 会被套件重启，十几秒后恢复，设置保留。安装失败时 rsagent 不会重启，页面显示失败原因（完整记录在 `/tmp/rsagent/update/pkg-apply.log`）。也可以在路由器上再执行一次在线安装命令升级。
- **用离线包安装的**：可以在“部署”页更新（下载到 `/tmp`，不占闪存）；也可以执行在线安装命令改为套件安装。
- **移除**：`opkg remove luci-app-rsagent rsagent`（25.x：`apk del luci-app-rsagent rsagent`）。服务会先停止；`/etc/rsagent` 里的设置与节点状态保留，重新安装后自动沿用，不需要时手动删除。tailscale 不会随之移除。
- tailscale 是 rsagent 套件的依赖，套件管理器会阻止单独移除它。若仍被移除（例如离线包安装、强制移除），LuCI 页面与管理界面会显示“未安装”并提供一键安装；rsagent 停止时 LuCI 页面同样会提示。
