# 远程串口桥接 Agent 开发方案与计划

- 项目代号：rsagent（Remote Serial Agent，暂定）
- 文档版本：v0.2，2026-10-14
- 状态：方案评审稿
- v0.2 变更：Windows 服务降为可选，部署改为自动登录加计划任务；确认 RFC2217 留在第三期，被测设备不以 ESP32 为主。
- v0.3 变更：新增部署页，计划任务、Windows 服务、防火墙、WebView2 均按需一键安装；安装包降为可选。

---

## 1. 背景与目标

### 1.1 要解决的问题

设备放在异地，需要从本地机器连上异地 PC 的串口做调试、看日志、烧录固件。异地 PC 通常在 NAT 后面，没有公网 IP，可能是运营商级 NAT。

### 1.2 方案选择结论

经过对比，采用"远端 agent 内嵌 Tailscale"方案，不自建中转平台。理由：

- Tailscale 提供 NAT 穿透、WireGuard 加密、身份认证和 ACL，无需自己维护基础设施。
- 大多数情况下能点对点直连，自建中转永远是两跳。
- 国内直连失败时，自有服务器可以分层补位：peer relay、自建 DERP、Headscale，全部零代码。
- 真正的难点在串口语义层（波特率、DTR/RTS、独占、热插拔），和网络通道无关，两种方案都要做。

### 1.3 产品目标

远端 PC 上运行一个单文件程序，具备：

1. 内嵌 Tailscale 节点，界面上用 auth key 登录，登录状态持久化，重启后自动上线。
2. 选择串口和通信参数，转成 TCP server，显示连接状态。
3. 提供 web 管理界面，本地通过 tailnet 直接在浏览器里打开。
4. 远端本机用 webview 原生窗口承载同一套 web 界面，带托盘图标。
5. 可作为 Tailscale subnet router，把远端局域网宣告到 tailnet。

### 1.4 非目标（第一版不做）

- 本地侧虚拟 COM 口驱动。本地继续用 com0com + hub4com 或直接支持 rfc2217:// 的工具。
- 多人协作、会话共享、云端用户体系。
- 自建中转平台。
- 硬件流控（RTS/CTS）。串口库当前不支持，列为已知限制。
- 安装包。程序自带部署页，Inno Setup 仅在批量分发时可选。

## 2. 总体架构

### 2.1 部署拓扑

```
 本地机器（你的电脑）                       远端站点
 ┌──────────────────────┐                 ┌────────────────────────────────────┐
 │ Tailscale 官方客户端  │                 │ rsagent.exe（单文件）               │
 │                      │   tailnet       │ ┌──────────┐ ┌──────────────────┐ │
 │ 浏览器 ──────────────┼────────────────►│ │ tsnet 节点│►│ HTTP/WS 管理界面 │ │
 │ esptool/pyserial ────┼── rfc2217:// ──►│ │ 100.x.y.z│►│ 串口桥接 TCP     │ │
 │ com0com+hub4com ─────┼── COMx 映射 ───►│ │          │►│ 子网路由转发     │ │
 │ 其他 LAN 设备访问 ───┼── subnet ──────►│ └──────────┘ └────────┬─────────┘ │
 └──────────────────────┘                 │                        │ COM1..n   │
                                          │  webview 窗口 + 托盘    ▼           │
            Tailscale 协调服务器            │  (127.0.0.1:7890)   [被测设备]     │
            DERP / peer relay / Headscale  └────────────────────────────────────┘
            （可落在自有服务器上）
```

### 2.2 进程模型

默认是单进程：`rsagent.exe` 启动后同时运行 core 和 shell 两个逻辑角色。服务模式按需在部署页开启。

| 角色 | 职责 | 单进程模式（默认） | 服务模式（部署页按需开启） |
|---|---|---|---|
| core | tsnet 节点、串口桥接、HTTP API、子网路由 | 与 shell 同进程 | Windows 服务 `rsagent service run` |
| shell | 托盘图标 + webview 窗口，窗口加载 `http://127.0.0.1:7890/` | 与 core 同进程 | 同一个 exe 启动时探测到服务在跑，自动进入 shell-only |

设计原则：shell 只通过本机 HTTP API 和 core 通信，不直接调用 core 的内部对象。这条边界让两种模式共用全部 UI 代码。

为什么默认不是服务：服务只解决"重启后无人登录桌面也要在线"这一个问题，但 Windows 服务不能显示窗口，必须拆两个进程并处理 session 0 权限。工控机通常本来就是自动登录，用计划任务能达到同样效果。两条路线的选择见 4.5。

单进程模式下关闭 webview 窗口只是最小化到托盘，托盘菜单"退出"才真正结束进程。服务模式下托盘"退出"只关 UI，不影响服务。

### 2.3 监听面

| 监听 | 地址 | 用途 | 访问控制 |
|---|---|---|---|
| 本机引导/控制 | `127.0.0.1:7890` | webview 窗口、首次登录、无 tailnet 时的配置 | 仅本机进程可达 |

本机监听即使在单进程模式下也保留，webview 窗口始终通过它访问页面，这就是 core/shell 的边界。
| tailnet 管理界面 | tsnet `:80`（可选 `:443` 自动证书） | 本地浏览器远程管理 | WhoIs 登录名白名单 |
| 串口桥接 | tsnet `:2217`、`:2218`…每个桥接一个端口 | 串口数据通道 | tailnet ACL |

串口桥接和管理界面都不绑定局域网网卡。局域网内其他机器看不到这些端口。

## 3. 技术选型

| 领域 | 选型 | 说明 |
|---|---|---|
| 语言 | Go 1.23+ | tsnet 只有 Go 版本，这一条锁定语言 |
| Tailscale | `tailscale.com/tsnet` | 进程内节点，用户态 netstack，无需管理员和驱动 |
| 串口 | `go.bug.st/serial` | 跨平台，支持枚举 VID/PID、SetDTR/SetRTS、Break、调制解调器状态位 |
| HTTP | 标准库 `net/http` + `embed` | 前端静态文件打进二进制 |
| WebSocket | `github.com/coder/websocket` | 状态推送、网页终端 |
| webview | `github.com/jchv/go-webview2` | 纯 Go，无 cgo，Windows 专用，依赖系统 WebView2 运行时 |
| 托盘 | `fyne.io/systray` | 无 cgo |
| 服务化 | `github.com/kardianos/service` | Windows 服务与 systemd 统一封装，部署页按需安装 |
| 日志 | `log/slog` + `gopkg.in/natefinch/lumberjack.v2` | 结构化日志 + 文件滚动 |
| 配置 | JSON，`encoding/json` | 单文件，带版本号便于迁移 |
| 前端 | Vue 3 + Vite + Naive UI | 构建产物进 `embed`；终端用 `@xterm/xterm` |
| 安装包 | Inno Setup | 注册服务、防火墙规则、WebView2 引导程序 |

选型说明：

- webview 用 go-webview2 而不是 Wails。UI 已经通过 HTTP 和 core 通信，不需要 Wails 的 Go/JS 绑定层，少一层复杂度，而且保持无 cgo 方便交叉编译。
- Linux/ARM 平台只构建 core 角色，不构建 shell。没有 PC 的站点放一个树莓派跑同一个 core。
- WebView2 运行时 Windows 11 自带。Windows 10 LTSC 可能没有，安装包附带 Evergreen 引导程序。

## 4. 模块设计

### 4.1 Tailscale 模块（`internal/tsnode`）

职责：封装 tsnet.Server 的生命周期和状态查询。

登录流程：

1. 界面输入 auth key、控制服务器地址（默认官方）、节点主机名（默认 `rs-<机器名>`）。
2. 创建 `tsnet.Server{AuthKey, Dir, Hostname, ControlURL, Port: 41641}`，调用 `Up(ctx)`，超时 60 秒。
3. 状态机：`NeedsLogin → Starting → Running`，若 key 未预授权则停在 `NeedsMachineAuth`，界面提示"等待管理员批准"。
4. `Running` 后启动管理界面监听和各桥接监听。
5. auth key 用完即丢，不写入配置文件。

状态持久化：节点状态存于 `Dir`（`%ProgramData%\RemoteSerial\tsstate`）。再次启动时 tsnet 发现已有状态会忽略 AuthKey，直接上线，"记住登录"自然成立。

登出/重置：调用 `LocalClient().Logout`，关闭 Server，删除状态目录，回到 `NeedsLogin`。

auth key 要求（写进使用文档）：

- reusable、pre-authorized、带 tag（如 `tag:serial-agent`）。
- 带 tag 的节点默认关闭节点密钥过期。不带 tag 的节点 180 天后掉线要人工重新认证。
- auth key 本身最长 90 天有效，只影响新设备入网。批量部署可改用 tsnet 的 `ClientID`/`ClientSecret` OAuth 方式。

状态查询：`LocalClient().Status(ctx)` 返回自身 IP、MagicDNS 名、每个 peer 的 `CurAddr`（非空即直连）和 `Relay`（DERP 区域）。

子网路由：`LocalClient().EditPrefs` 设置 `AdvertiseRoutes`。审批状态对比 `Self.AllowedIPs` 与已宣告列表。

固定 UDP 端口 41641，安装时为 exe 加入站 UDP 防火墙规则，提高直连成功率。

### 4.2 串口桥接模块（`internal/bridge`）

数据模型（从第一天就支持多串口）：

```json
{
  "id": "b1",
  "name": "主控板调试口",
  "port": "COM3",
  "match": { "vid": "1A86", "pid": "7523", "serial": "" },
  "baud": 115200,
  "dataBits": 8,
  "parity": "N",
  "stopBits": 1,
  "mode": "raw",
  "tcpPort": 2217,
  "clientPolicy": "replace",
  "idleTimeoutSec": 0,
  "enabled": true
}
```

- `match` 可选。USB 串口重新枚举后 COM 号可能变，按 VID/PID/序列号匹配比按 COM 号稳。
- `mode`：`raw`（第一期）或 `rfc2217`（第三期）。
- `clientPolicy`：`reject` 拒绝新连接，`replace` 踢掉旧连接。

运行时行为：

- 每个桥接一个 goroutine 管理串口打开、TCP 监听、数据泵。
- TCP 连接设置 `TCP_NODELAY`、keepalive 10 秒。空闲超时可配，默认关闭。
- 串口被拔出：关闭串口，状态置为"等待设备"，每 3 秒重试打开，TCP 连接保持不断。
- 统计：收发字节数、连接时长、客户端 tailnet 身份（WhoIs）、最近错误。
- 每个桥接保留一个 64KB 环形缓冲，供网页终端打开时回显最近输出。

RFC2217 模式（第三期）：

- 实现 telnet 协商：BINARY(0)、SUPPRESS-GO-AHEAD(3)、COM-PORT-OPTION(44)。
- 实现子命令：SET-BAUDRATE、SET-DATASIZE、SET-PARITY、SET-STOPSIZE、SET-CONTROL（DTR/RTS）、PURGE-DATA、NOTIFY-MODEMSTATE、SET-MODEMSTATE-MASK。
- 数据流中转义 `0xFF`。
- 客户端修改参数后，界面显示"当前参数由客户端设置"并展示实际值。
- 互操作测试对象：pyserial `rfc2217://`、esptool、hub4com `com2tcp-rfc2217`。

### 4.3 Web 管理界面（`internal/web` + `web/`）

页面：

| 页面 | 内容 |
|---|---|
| 概览 | 节点状态、IP、MagicDNS、各桥接一行状态、告警 |
| Tailscale | 登录表单、状态机、登出/重置、控制服务器地址、主机名、peer 列表及直连/中转 |
| 串口桥接 | 桥接列表增删改、串口下拉（带 USB 描述）、参数、启停、实时统计 |
| 子网路由 | CIDR 列表、宣告开关、审批状态、局限说明 |
| 终端 | xterm.js，选择桥接后直通串口，只读/读写切换（第三期） |
| 日志 | 最近 1000 行内存日志，级别过滤，下载日志文件 |
| 部署 | 检测项与一键按钮：开机自启计划任务、Windows 服务、防火墙规则、WebView2、自动登录状态，见 4.5 |
| 设置 | 访问白名单、日志级别、数据目录、版本与更新检查 |

鉴权中间件：

- 来自 `127.0.0.1` 监听：完全信任。
- 来自 tsnet 监听：调用 `WhoIs(RemoteAddr)`，登录名不在白名单则 403。白名单为空时允许所有 tailnet 用户，但界面显示告警。

### 4.4 桌面壳（`internal/shell`，仅 Windows）

- 托盘菜单：打开控制台、节点状态（只读）、打开数据目录、退出。
- webview 窗口加载 `http://127.0.0.1:7890/`，大小 1100×720，关闭即最小化到托盘。
- 启动时轮询 core 的 `/api/status`，core 未就绪显示"正在启动"页。
- 单实例保护：启动时检测本机 7890 端口已被自己占用则直接唤起已有窗口并退出。

### 4.5 部署（`internal/deploy`、`deploy/`）

程序自带部署能力，不依赖安装包。把 exe 复制到远端，双击运行，登录 tailnet 后在"部署"页按需点按钮。

部署页的检测项与按钮：

| 检测项 | 按钮 | 需要提权 | 说明 |
|---|---|---|---|
| 开机自启计划任务 | 安装 / 卸载 | 否（当前用户登录触发） | 触发器"用户登录时"，每 5 分钟重复，已运行则不启动新实例。同时实现自启和崩溃拉起 |
| Windows 服务 | 安装 / 卸载 | 是 | core 跑在服务里，当前托盘程序自动切到 shell-only 模式 |
| 防火墙规则 | 添加 | 是 | UDP 41641 入站，提高直连成功率 |
| WebView2 运行时 | 安装 | 是 | 检测注册表，缺失时下载 Evergreen 引导程序执行 |
| 自动登录 | 仅显示状态与说明 | 否 | 读取 AutoAdminLogon 键显示是否已配置；不代存密码，说明页指引用 Sysinternals Autologon |
| 运行模式 | 无 | 否 | 显示"单进程"或"服务 + shell" |

提权方式：core 收到部署请求后，以 `runas` 动词重新拉起 `rsagent.exe deploy <action>` 子进程，由提权后的子进程执行 schtasks、sc、netsh。父进程等待退出码并返回结果。

远程点按钮的限制：UAC 提示出现在远端的安全桌面上，远端无人时没人确认。应对：首次部署在现场完成，安装计划任务时勾选"以最高权限运行"，之后程序本身就是提权状态，后续从本地远程点按钮不再弹 UAC。部署页在未提权时显示这条提示。

两种无人值守路线，按站点选择：

- **路线 A，自动登录 + 计划任务**：适合工控机。用 Autologon 配自动登录，密码存为 LSA secret。现场有人经过就再加一个登录后自动锁屏的任务，锁屏不影响托盘程序。
- **路线 B，Windows 服务**：适合不允许自动登录的站点。点"安装服务"后 core 以服务运行，托盘程序只剩 UI。

运行模式切换规则：程序启动时探测 `127.0.0.1:7890`。若已有 rsagent 在服务（通过 `/api/status` 的 `mode` 字段识别），当前进程进入 shell-only 模式，只起托盘和窗口；否则以单进程模式启动 core。同一机制也兼作单实例保护。

数据目录 `%ProgramData%\RemoteSerial\`：`config.json`、`tsstate\`、`logs\`。单进程和服务模式共用，切换不迁移。服务安装时为该目录授予服务账户权限。

Linux/ARM 站点：core 以 systemd 服务运行，`deploy/systemd/` 提供 unit 模板，无 shell。

Inno Setup 安装包降为可选，仅用于批量分发时省去手工复制。

### 4.6 子网路由

- 界面输入 CIDR 列表，保存后调用 EditPrefs 宣告。
- 审批：推荐在 ACL 里配 `autoApprovers`，远端上线即生效。
- 用户态转发局限写在界面提示里：仅 TCP/UDP，ping 不通属正常；源地址做 SNAT；不要宣告与本地重叠的网段。
- 本地 Linux 客户端需要 `--accept-routes`，Windows 默认接受。

ACL 模板（`deploy/acl.example.json`）：

```json
{
  "tagOwners": { "tag:serial-agent": ["autogroup:admin"] },
  "autoApprovers": {
    "routes": { "192.168.10.0/24": ["tag:serial-agent"] }
  },
  "acls": [
    {
      "action": "accept",
      "src": ["autogroup:member"],
      "dst": ["tag:serial-agent:80,443,2217-2299", "192.168.10.0/24:*"]
    }
  ]
}
```

### 4.7 日志与诊断

- slog 双输出：文件滚动 + 内存环形缓冲供界面读取。
- 串口流量录制（第三期）：按桥接开关，写入 `logs\capture-<id>-<时间>.bin`。
- 诊断页（第三期）：peer 直连/中转、最近一次 DERP 延迟、netcheck 摘要。依据这页决定是否在自有服务器上部署 peer relay 或 DERP。

## 6. 关键决策与风险

| 编号 | 事项 | 决策/应对 |
|---|---|---|
| R1 | 节点密钥 180 天过期导致远端掉线 | 强制使用带 tag 的 auth key，文档和界面都提示 |
| R2 | 国内打洞失败走香港/东京 DERP，延迟高 | 诊断页暴露直连/中转；自有服务器按 peer relay → DERP → Headscale 逐级补位，界面预留控制服务器地址 |
| R3 | 本地断网后远端串口被死连接占住 | keepalive 10 秒 + 可配空闲超时 + 界面"踢掉客户端"按钮 |
| R4 | USB 串口重枚举后 COM 号漂移 | 按 VID/PID/序列号匹配，COM 号只作兜底 |
| R5 | 裸 TCP 无法改波特率、拉 DTR/RTS，ESP32 自动复位失败 | 第三期实现 RFC2217，界面显示客户端设置的参数 |
| R6 | 远端停在登录界面导致程序不在线 | 部署页提供两条路线：自动登录加计划任务，或按需安装 Windows 服务 |
| R15 | 远程点部署按钮时 UAC 无人确认 | 首次部署在现场完成并勾选最高权限运行；部署页未提权时明确提示 |
| R13 | 自动登录状态下现场人员可直接操作桌面 | 登录后自动锁屏的计划任务；托盘程序在锁屏下照常运行 |
| R14 | 用户注销会结束托盘程序 | 使用说明明确"锁屏不注销"；计划任务在重新登录后 5 分钟内拉起 |
| R7 | WebView2 运行时缺失 | 安装包附带 Evergreen 引导程序，shell 启动时检测并提示 |
| R8 | tsnet 随机 UDP 端口被防火墙拦截 | 固定 41641，安装包加防火墙规则 |
| R9 | 管理界面被 tailnet 内其他用户访问 | WhoIs 白名单 + ACL 双重限制 |
| R10 | 硬件流控不支持 | 第一版标记已知限制，后续评估替换串口库 |
| R11 | 子网与本地网段重叠 | 界面校验并警告，文档建议改址或使用 4via6 |
| R12 | 设备数配额 | 每个 agent 实例占一个节点，免费版 100 台 |

## 7. 开发计划

工作量按一名开发者配合 AI 辅助估算，单位为工作日，属于粗略估计。

### 第 0 期：工程骨架（2 天）

|---|---|

### 第 1 期：MVP，单进程可用（8 到 10 天）

| 任务 | 交付 |
|---|---|
| tsnode：登录、状态机、持久化、登出重置 | 界面输入 auth key 上线；重启后自动上线 |
| bridge：串口枚举、单桥接 raw TCP、统计 | 本地 `nc 100.x.y.z 2217` 收发串口数据 |
| web：概览、Tailscale、串口桥接三个页面，`/ws/events` 推送 | 本地浏览器打开 `http://rs-xxx/` 可操作 |
| shell：托盘 + webview 窗口 | 远端双击 exe 出原生窗口 |
| 鉴权中间件 | 本机信任，tailnet 侧 WhoIs 白名单 |

验收：

- 远端重启并自动登录后 60 秒内节点上线，桥接自动恢复。
- 拔插 USB 串口，桥接 10 秒内恢复，TCP 连接不断。
- 本地断网 30 秒内远端释放串口，新连接可接入。
- 本地浏览器通过 MagicDNS 名打开管理页，修改波特率后生效。

### 第 2 期：部署页与子网路由（7 到 8 天）

| 任务 | 交付 |
|---|---|
| 多桥接、VID/PID 匹配、clientPolicy | 两个串口同时桥接 |

| 提权子进程 `rsagent deploy <action>` | 未提权时弹 UAC 并执行 |
| Windows 服务安装/卸载按钮，服务模式 core，启动时探测服务进入 shell-only | 点"安装服务"后重启无需登录即上线 |
| 单实例保护、崩溃后计划任务拉起验证 | 结束进程后 5 分钟内自动恢复 |
| 子网路由页面、EditPrefs、审批状态 | 本地访问远端局域网设备网页 |

| 使用说明文档：auth key 制作、Autologon、锁屏任务、ACL 模板 | `docs/使用说明.md` |

验收：

- 路线 A：点"安装计划任务"，配好自动登录后重启，不做任何操作 60 秒内上线。

## 9. 已确认事项

- webview 原生窗口为必需。
- 被测设备不以 ESP32 类为主，RFC2217 保持在第三期。
- Windows 服务不是必需。程序自带部署页，计划任务和服务都按需一键安装，不做安装包。

## 10. 待确认问题

1. 远端机器操作系统分布：是否全部 Windows，有没有 Linux 工控机或树莓派。
2. 每个站点串口数量上限，影响默认端口范围。
3. 是否需要多人同时只读查看同一个串口。
4. Headscale 是否在第一期就要验证。
5. 前端 UI 库偏好，默认 Naive UI。
